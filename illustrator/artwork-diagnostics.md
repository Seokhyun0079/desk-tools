# 要素一覧の診断（基本件数のみ）

旧版v1は文書全体やグループのコレクションを繰り返し走査し、実環境でIllustratorが応答しなくなる報告がありました。旧版は再実行しないでください。v2は要素の列挙・階層再帰・親の照合・UUID比較・既存UIの再走査を削除しています。

1. メイン版の `artwork-diagnostics.jsx` をダウンロードし、旧ファイルを置き換えます。
2. 調べる文書を開き、ファイル → スクリプト → その他のスクリプトから実行します。オーバーレイの一覧を再構築しなくても、文書の種類別件数は取得できます。
3. 結果欄をクリックして Ctrl/Cmd+A → Ctrl/Cmd+C でコピーします。冒頭が `desk-tools-artwork-diagnostic-v2` になっていることを確認してください。

ウィンドウを表示してから、文書直下の13個の種類別コレクションの長さを各1回読みます。個別要素、親、下位階層、既存ツリーにはアクセスしません。コレクション間で同じ要素が含まれるため件数を合算しません。Illustratorの個別プロパティ呼び出し自体が遅い場合は待機が生じ得ます。この処理は非同期ではありません。

最新オーバーレイを実行済みの場合は、既存ローダーが作った純粋な数値データの種類別件数も表示します。診断用にオブジェクトを再走査しません。`OverlaySnapshot=unavailable` の場合も基本件数を利用できます。診断のために重い一覧を再構築する必要はありません。

読み取り専用です。文書名、オブジェクト名、文字内容、画像データ、ファイル名、座標、UUIDを取得しません。ファイル保存、通信、選択変更、オブジェクト編集は行いません。例外文も出力しません。

テスト: `node illustrator/tests/artwork-diagnostics.test.cjs` と `node illustrator/tests/green-overlay.test.cjs`。10億要素相当のモックでも個別要素へのアクセス0回、コレクション長の問い合わせ回数が一定、最初の文書問い合わせより前にウィンドウ表示、私有データ取得なし、キャッシュ件数を確認します。実際のIllustratorでの応答時間は未確認です。
