## 2026-10-02 — 열자마자 읽기 실패

기준 커밋: `583f26a`, 대상 브랜치: `cursor/fix-green-overlay-spec-89db`.

### 원인

두 경로가 같은 증상으로 보인다.

1. 한글 Illustrator는 BOM 없는 UTF-8 JSX를 시스템 코드 페이지로 읽는다. 이 파일은 일본어 UI 때문에 ASCII가 아니므로, 스크립트가 시작되기 전에 `읽기에 실패했습니다`만 뜨고 팔레트가 나오지 않을 수 있다.
2. 파일을 읽은 뒤에는 계층 로딩이 `読み込みに失敗しました`에서 멈추고 목록과 실행이 비활성화됐다. 분할 로딩 메시지가 `#targetengine`과 `$.global.__greenOverlayLoadStep` 호출을 본문에 넣었다. Illustrator는 BridgeTalk 본문에 `#targetengine`을 적용하지 않아 본문은 기본 엔진에서 실행된다. 팔레트 함수는 그 엔진에 없으므로 메시지 오류가 나고, 오류 처리가 로딩을 끈 뒤 다시 진행하지 않았다.

같은 제약으로 실행 경로가 이미 실패한 적이 있다 (`b8c064f`). 당시에는 팔레트 함수 호출을 제거하고 본문을 자체 완결 스크립트로 바꿨다. 이번 로딩은 그 수정을 되돌린 형태였다. 모의 테스트는 본문의 `#targetengine`을 지운 뒤 팔레트와 같은 컨텍스트에서 실행해 엔진이 나뉜 오류를 보지 못했다.

### 수정

- `green-overlay.jsx`는 UTF-8 BOM으로 저장한다. `#target` 지시는 BOM 다음에 둔다.
- BridgeTalk 본문은 `'ok';`만 보낸다. 팔레트 전역 함수를 호출하지 않고 `#targetengine`을 넣지 않는다.
- 계층 조회와 트리 생성은 메시지를 보낸 엔진의 `onResult`에서 이어 간다.
- 메시지 전송 실패나 대상 오류가 나면 같은 단계를 팔레트 엔진에서 끝까지 수행한다. 목록을 끈 채로 두지 않는다.
- 취소·닫기·다른 세션의 늦은 콜백은 작업 번호를 비교해 무시한다.
- 테스트는 로딩 본문을 팔레트 전역이 없는 별도의 기본 엔진에서 실행한다.

### 재발 방지

JSX를 BOM 없는 UTF-8로 다시 저장하지 않는다. BridgeTalk 본문에서 팔레트 엔진의 함수나 `$.global` 로더를 호출하지 않는다. `#targetengine`을 본문에 넣어 엔진을 바꾸려 하지 않는다. 팔레트 상태 변경은 `onResult`처럼 보낸 쪽에서 실행되는 콜백에서만 한다. 테스트가 본문을 팔레트와 같은 전역에서 실행하면 이 실패를 통과로 기록하지 않는다.

### 검증

`node illustrator/tests/green-overlay.test.cjs`

- 로딩 본문에 `#targetengine`과 `__greenOverlayLoadStep`이 없고, 빈 기본 엔진에서 실행해도 예외가 없다.
- 완료 콜백으로 1,000개 대상을 여러 메시지에 나눠 구성한다.
- 취소 뒤 남은 콜백은 조회하지 않는다.
- 메시지 오류 콜백 뒤에는 팔레트 엔진에서 트리를 마치고, 읽기 실패 경고를 띄우지 않으며 목록을 다시 켠다.

실제 Illustrator의 자가 BridgeTalk 지연과 인라인 대체 체감은 미검증이다. 모의 통과를 실제 환경 성공으로 기록하지 않는다.

## 2026-10-02 — 열린 문서인데 930행에서 문서가 아니라는 오류

기준: `cursor/fix-load-read-failure-8017`의 로딩 콜백. 사용자가 연 파일은 손상된 문서가 아니다.

### 원인

계층 로딩이 시작 때 잡아 둔 문서 대신, 매 단계에서 `app.activeDocument`를 다시 읽고 `sameItem`으로 비교했다. 팔레트 콜백에서 이 조회는 문서가 열려 있어도 `This is not a document`(한글 UI: 이것은 문서가 아닙니다)를 던진다. 그 예외가 930행에서 스크립트 오류 대화상자로 표시되고 로딩이 중단됐다.

문서 객체는 z-order가 없어, 비교가 예외 없이 실패해도 같은 문서를 다른 문서로 볼 수 있다.

### 수정

- 열린 문서가 하나도 없을 때만 로딩을 중단한다.
- 활성 문서 재조회가 실패하면 한 번만 기록하고, 시작 시 잡아 둔 문서로 계층 읽기를 계속한다.
- 활성 문서 이름이 달라도 원래 문서가 아직 열려 있으면 그 문서를 계속 읽는다.

### 검증

모의 테스트에서 두 번째 `activeDocument` 접근이 위 오류를 던지게 했다. 경고 없이 트리가 완성된다. 실제 Illustrator 콜백에서의 문구는 미검증이다.
