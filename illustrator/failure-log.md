# Illustrator 툴 실패·재발 방지 기록

## 2026-10-07 — 하위 표시 복구 후 남은 레이어 오류·파일 분할

기준: `main`의 `ba2f3df` (PR #8). 사용자가 하위 표시 복구는 확인했으나 오류가 남는다고 보고했고 파일 분할을 요청했다. 이번 오류의 정확한 문구/실제 호스트 원인은 추가로 확인하지 못했다.

확인한 위험: 버튼 선택 시 저장된 네이티브 참조로 전체 하위 요소의 경계를 직접 읽었다. 한 경계가 예외를 던지면 선택이 중단됐다. 표시 상태 실패만 완화한 이전 수정으로는 이 경로를 해결하지 못했다.

수정: 레이어 선택/해제는 모델의 주소 데이터만 사용한다. 초기 로더가 이미 읽는 컬렉션에서 레이어 인덱스 경로와 이름을 저장하고, 미리보기·생성은 호스트의 실제 문서에서 레이어를 다시 찾아 계산한다. 모든 레이어 범위를 생성 전에 확정한다. 미리보기 실패는 로그에 남기고 UI 선택/하위 목록을 유지한다. 복합 패스의 경계는 구성 패스로 복원할 수 있고, 자식 경계가 읽히지 않는 비클리핑 그룹은 그룹 자체 경계를 대체 사용하며 결과에 근사를 알린다. 해결할 수 없는 레이어는 해당 대상만 실패로 보고하여 일반 대상 생성까지 중단하지 않는다. 일반 대상만 실행하면 레이어 전용 호스트 함수를 직렬화하지 않는다.

분할: 진입 `green-overlay.jsx` 약 1.5KB와 logging/model/bounds/ui/bridge/tree/execute/actions `.jsxinc`로 분리했다. 동일 IIFE 스코프·기존 엔진을 유지한다. 진입 파일과 포함 폴더를 함께 배포해야 하며 README에 ZIP 설치를 명시했다. #include는 소스를 합치는 전처리이므로 분할만으로 속도가 개선됐다고 주장하지 않는다.

검증: 기존 계층·개폐·선택·설정·생성·진단 검사, 레이어 범위 검사를 유지했다. 새 모의 상황에서 초기 참조의 경계 조회가 이후 예외를 던져도 선택/미리보기/생성이 새 참조를 사용함을 확인했다. 비어 있는/숨긴/경계 취득 불가 레이어는 선택을 중단하지 않고 생성 때 보고한다. 그룹 경계 대체, 복합 마스크 경계 복원, 한 레이어 실패와 정상 일반 대상 생성 병행, 생성 전 모든 레이어 범위 확정, 모듈을 공백/비ASCII 폴더로 옮겨 상대 include/BOM을 유지하는 것, 누락 include 검출, 일반 대상만의 호스트 코드가 레이어 함수로 커지지 않는 것을 확인했다. 레이어 호스트 콜백에서도 최초 문서 래퍼의 layers 속성이 일시적으로 읽히지 않으면 현재 문서 핸들을 다시 취득하는 검사를 통과했다. 동작하던 addObjectNodes/refreshVisibleObjectRows/drawOne은 그대로 유지했다.

실제 Illustrator의 오류 해결 여부와 시간 개선 폭은 미확인이다. 새 문구·로그가 남으면 단계에 맞춰 원인을 좁힌다.

## 2026-10-07 — 레이어 대상 추가 후 표시 상태 오류·하위 목록 누락 (사용자 보고)

기준: `main`의 `5c93709` (PR #7). 사용자가 `表示状態を取得できません。` 오류와 기존 레이어 하위 요소의 표시 누락을 보고했다. 실제 문서는 미확인이다.

확인한 실패 경로: 새 범위 계산은 `Layer.visible` 또는 아트의 `hidden` 속성 하나가 예외를 던지면 전체 레이어 선택을 중단했다. 기존 테스트에는 이 호스트 속성 조회 실패가 없었다. 하위 표시 누락의 정확한 네이티브 원인은 확정하지 못했으며, 추가 레이어 대상 행과 펼침 호출을 기존 TreeView 구성 안에 넣었던 변경을 제거한다.

수정: `addObjectNodes`, `refreshVisibleObjectRows`, `drawOne`은 사용자가 말단 표시 동작을 보고한 `c4cfd68` 버전으로 복구했다. 트리 안의 레이어 대상 행을 없애고 대상 목록 위 별도 버튼으로 레이어 전체 선택/해제를 처리한다. 레이어 행을 선택해도 기본 화살표 상태를 바꾸거나 생성 대상으로 자동 선택하지 않는다. 표시 상태 조회가 실패한 요소는 경계를 읽을 수 있으면 포함하고 상태줄·로그에 불확실성을 남긴다. 숨김이 확인된 요소의 제외, 경계를 읽지 못하는 경우 생성 중단, 실행 전 범위 갱신은 유지한다. UI 모델에 저장한 타입을 범위 순회에서 사용한다.

검증: 기존 트리/개폐/말단 1000개/같은 행 토글/하위 전체/RGB·투명도/생성 실패/문서 재연결/혼합 타입 및 레이어 범위 검사를 유지했다. `visible`과 `hidden`이 예외를 던져도 경계는 읽히는 레이어·그룹·패스 상황을 재현하여 선택·해제, 실제 실행 전 계산, 숨김이 확인된 다른 아트의 제외, 상태 메시지/로그, 하위 UI 행의 동일성·순서 보존을 확인했다. 대상 버튼은 그룹 행으로 이동하면 비활성화되어 이전 레이어를 잘못 토글하지 않는다. 기본 진단 검사도 통과했다.

실제 Illustrator에서 하위 표시 복구와 새 버튼 동작은 아직 미확인이다. 모의 검사를 실제 호스트 성공으로 간주하지 않는다.

## 2026-10-07 — 레이어 전체를 하나의 생성 대상으로 선택

기준: `main`의 `c4cfd68`. 사용자가 이전 말단 표시 수정은 동작하는 것 같다고 보고한 뒤, 레이어 전체 선택 기능을 승인했다.

변경: 레이어 안에 `このレイヤーを対象にする` 전용 토글 행을 추가했다. 부모 레이어 이름의 개폐, 하위 전체 토글, 개별 선택을 변경하지 않는다. 레이어 대상은 하위 요소의 표시 경계를 합쳐 사각형 하나를 만들며, 레이어/개별 요소를 함께 선택하면 각각 생성한다. 전체 선택은 기존 개별 대상에만 적용하고 전체 해제는 레이어 대상도 해제한다.

범위: 선택 시 이미 읽은 모델을 사용하고 실행 확인 후 실제 DOM에서 다시 계산한다. 숨긴 요소·숨긴 상위 레이어·가이드를 제외하고 표시 중인 잠긴 요소는 포함한다. 클리핑 그룹은 마스크의 기하 경계와 내용 경계를 교차한다. 비사각형 마스크는 경계 사각형 근사이며, 그룹·레이어 자체 외관 효과 확장은 이 계산 범위 밖이다. 비거나 범위를 읽을 수 없는 레이어를 임의의 다른 선택 객체로 대체하지 않는다. 같은 실행에서 만든 사각형이 후속 레이어 크기에 포함되지 않도록 모든 레이어 범위를 생성 전에 확정한다.

검증: 기존 트리·네이티브 개폐·같은 행 반복 토글·하위 전체 선택·RGB/투명도·생성 실패 로그·문서 재연결·혼합 타입/중복 제거 검사를 유지했다. 새 검사로 레이어 행과 개별 선택의 독립성, 시작 시 추가 경계/컬렉션 조회 부재, 중심 이동, 하위 레이어/동일 이름, 숨김/가이드 제외, 잠긴 아트 포함, 일반/복합 클리핑 패스, 선 굵기 포함, 실행 직전 이동/추가, 소스 레이어에 생성하는 동안 범위 고정, 빈/숨김/읽기 실패, 다른 선택 객체로 잘못 대체하지 않음을 확인했다. 기본 진단 검사도 통과했다.

실제 Illustrator에서의 새 기능 동작은 이 환경에서 확인하지 못했다. 모의 통과를 실제 호스트 성공으로 기록하지 않는다.

## 2026-10-06 — 진단 스크립트 실행 시 Illustrator 멈춤 (사용자 보고)

대상: `artwork-diagnostics.jsx` v1, 메인 `2a13658`. 사용자가 실행 시 Illustrator가 멈췄다고 보고했다. 실제 호스트의 정확한 병목은 실측하지 못했다.

확인한 코드 위험: 문서 전체의 `pageItems`를 읽은 뒤 모든 레이어·그룹의 종류별 컬렉션을 반복 조회했다. 최대 100000개 요소 관찰과 2048개 컨테이너라는 제한은 개별 DOM 호출·중복 조회의 실제 시간을 제한하지 않는다. 컨테이너 참조를 선형으로 비교하여 수가 많을수록 비교량도 제곱으로 늘었다. 진단 창은 이 모든 처리가 끝난 뒤 표시했다. 기존 모의 테스트는 호스트 호출 비용을 반영하지 않아 이 구조를 통과시켰다.

수정: v2에서는 개별 요소 열거·계층 순회·부모 판정·UUID 비교·기존 UI 재순회를 전부 제거했다. 창을 먼저 표시하고 문서 직속 13개 컬렉션의 길이만 각 1회 조회한다. 오버레이 로더는 이미 보유한 `itemType` 문자열로 종류별 숫자 캐시를 저장하며, 진단은 그 순수 데이터만 읽는다. 목록을 다시 만들지 않아도 기본 진단을 실행할 수 있다.

검증: 10억 요소 상당 모의 컬렉션에 대해 개별 요소 접근 0회, 고정된 길이 조회 횟수, 창 표시 이후 문서 접근, 기밀 필드 접근 부재, 예외 메시지 비노출을 확인한다. 기존 목록·선택·생성 설정 검증과 숫자 캐시 검증도 수행한다. 개별 Illustrator DOM 속성 호출은 자체적으로 멈출 수 있으므로 실제 환경에서 정지 가능성이 0이라고 주장하지 않는다.

## 2026-10-06 — 텍스트와 그룹은 보이는데 이미지 등 다른 요소가 누락됨

기준: `main`의 `9646b0a`. 실제 문서는 미확인 상태이며 다음 누락 경로는 모의 문서에서 재현했다.

### 원인

- 초기 로더는 `pageItems` 조회 후 일부 종류만 보충했다. 텍스트 등 다른 아트가 이미 있으면 `placedItems`, `rasterItems`, `symbolItems`, `groupItems`, `compoundPathItems`, `textFrames` 보충 조회가 생략됐다.

- 중복 제거 키는 정렬 메타데이터가 없는 경우에도 `RasterItem#undefined` 같은 문자열을 만들었다. 같은 종류의 서로 다른 요소가 하나로 줄어들 수 있었다.

### 수정

- 레이어/그룹에서 모든 종류별 컬렉션의 직접 자식을 항상 합친다. 하위 그룹의 이미지를 상위 레이어로 끌어올리지 않고 반복 조회된 요소는 한 번만 표시한다.
- UUID, 유효한 숫자 정렬 번호 순서로 중복 제거 키를 만든다. 둘 다 없으면 객체 참조로만 중복을 제거한다. `undefined`나 이름만으로 서로 다른 요소를 합치지 않는다.
- 기존 UTF-8 BOM, 기본 트리 개폐, 선택 방식 및 생성 설정을 유지한다.

### 검증

- 연결 이미지, 래스터 이미지, 심볼, 그룹, 복합 패스 및 나머지 종류별 아트가 혼합된 계층에서 누락/중복 없이 표시되는지 확인한다.

## 2026-10-02 — 열자마자 읽기 실패

기준 커밋: `583f26a`, 대상 브랜치: `cursor/fix-green-overlay-spec-89db`.

### 원인

두 경로가 같은 증상으로 보인다.

1. 한글 Illustrator는 BOM 없는 UTF-8 JSX를 시스템 코드 페이지로 읽는다. 이 파일은 일본어 UI 때문에 ASCII가 아니므로, 스크립트가 시작되기 전에 `읽기에 실패했습니다`만 뜨고 팔레트가 나오지 않을 수 있다.
2. 파일을 읽은 뒤에는 계층 로딩이 `読み込みに失敗しました`에서 멈추고 목록과 실행이 비활성화됐다. 분할 로딩 메시지가 `#targetengine`과 `$.global.__greenOverlayLoadStep` 호출을 본문에 넣었다. Illustrator는 BridgeTalk 본문에 `#targetengine`을 적용하지 않아 본문은 기본 엔진에서 실행된다. 팔레트 함수는 그 엔진에 없으므로 메시지 오류가 나고, 오류 처리가 로딩을 끈 뒤 다시 진행하지 않았다.

같은 제약으로 실행 경로가 이미 실패한 적이 있다 (`b8c064f`). 당시에는 팔레트 함수 호출을 제거하고 본문을 자체 완결 스크립트로 바꿨다. 이번 로딩은 그 수정을 되돌린 형태였다. 모의 테스트는 본문의 `#targetengine`을 지운 뒤 팔레트와 같은 컨텍스트에서 실행해 엔진이 나뉜 오류를 보지 못했다.

### 수정

- `green-overlay.jsx`는 UTF-8 BOM으로 저장한다. `#target` 지시는 BOM 다음에 둔다.
- BridgeTalk 본문은 `'ok';`만 보낸다. 팔레트 전역 함수를 호출하지 않고 `#targetengine`을 넣지 않는다.
- 계층 조회와 트리 생성은 메시지를 보낸 엔진의 `onResult`에서 이어 간다.
- 메시지 전송 실패나 대상 오류가 나면 같은 단계를 팔레트 엔진에서 끝까지 수행한다. 목록을 끈 채로 두지 않는다.
- 취소·닫기·다른 세션의 늦은 콜백은 작업 번호를 비교해 무시한다.
- 테스트는 로딩 본문을 팔레트 전역이 없는 별도의 기본 엔진에서 실행한다.

### 재발 방지

JSX를 BOM 없는 UTF-8로 다시 저장하지 않는다. BridgeTalk 본문에서 팔레트 엔진의 함수나 `$.global` 로더를 호출하지 않는다. `#targetengine`을 본문에 넣어 엔진을 바꾸려 하지 않는다. 팔레트 상태 변경은 `onResult`처럼 보낸 쪽에서 실행되는 콜백에서만 한다. 테스트가 본문을 팔레트와 같은 전역에서 실행하면 이 실패를 통과로 기록하지 않는다.

### 검증

`node illustrator/tests/green-overlay.test.cjs`

- 로딩 본문에 `#targetengine`과 `__greenOverlayLoadStep`이 없고, 빈 기본 엔진에서 실행해도 예외가 없다.
