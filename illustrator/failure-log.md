- 생성 위치에서는 자식 유무 확인과 재귀 진입 때 동일 계층을 반복 조회했다.
- 대상에서는 하위 요소가 없는 일반 오브젝트에도 컬렉션 조회 및 여러 타입별 대체 조회를 시도했다.
- BridgeTalk의 실행 실패와 생성 단계 오류 대부분이 무시되거나 일회성 메시지로만 남았다.

### 수정

- 창을 먼저 표시하고 최상위 레이어만 초기 구성한다.
- 대상 목록은 컨테이너 행을 펼칠 때 자식 모델을 읽는다. 생성 위치 트리도 펼침 이벤트에서 읽으며 같은 모델을 공유한다.
- 일반 오브젝트에는 하위 컬렉션 조회를 하지 않는다. 컬렉션 길이는 반복문 밖에서 한 번 읽는다.
- 전체 선택과 하위 전체 토글은 접힌 계층을 필요할 때 순회한다.
- 기존 ListBox 선택/접기 UI, 하위 전체 선택 행, RGB·투명도, BridgeTalk 생성 코드를 유지한다.
- 사용자 데이터 폴더에 시작 및 계층 조회 시간, 선택·크기·화면 이동·BridgeTalk·생성 오류를 기록한다. 호스트 실행 코드에도 로거를 포함한다.

## 2026-10-02 — 지연 로딩 후 양쪽 펼침 회귀 (사용자 보고)

이전 커밋 `7be9c14` 적용 후 양쪽 화살표가 열리지 않는다는 실제 환경 보고를 받았다. 위쪽은 TreeView의 펼침 이벤트에서 자식을 추가했고 아래쪽은 ListBox 문자 화살표와 선택 이벤트로 목록을 다시 그렸다. 모의 이벤트 직접 호출 테스트는 실제 호스트의 펼침 문제를 검출하지 못했다. 정확한 호스트 내부 원인은 실제 환경 미확인 상태다.

수정: 양쪽을 기본 TreeView로 통일하고 자식 노드는 표시 전에 구성한다. 컨테이너 선택 이벤트는 개폐를 변경하지 않으며 기본 화살표만 개폐를 담당한다. 하위 전체 선택 행과 일반 오브젝트 선택은 선택 이벤트로 처리한다. 선택 해제 시 화면 이동을 생략한다.

성능 경계: 지연 로딩은 철회했다. 최초에는 전체 계층을 한 번 읽지만 두 트리가 공유하고, 일반 오브젝트에 대한 불필요한 자식 조회는 생략한다. 시작 속도의 실제 개선 폭은 실측하지 않았다.

검증: 두 목록 TreeView, 컨테이너당 한 번 조회, 기본 펼침 상태를 선택 이벤트가 뒤집지 않음, 하위 전체 토글, 동일 항목 반복 토글, RGB·투명도와 호스트 실패 로그를 모의 환경에서 확인한다. 실제 마우스 화살표 동작은 Illustrator에서 재확인이 필요하다.
